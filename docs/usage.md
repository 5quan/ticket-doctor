# 产品使用说明

## 一、它是什么

在飞书群里提交 Bug 后，机器人在“开发接手前”自动查日志、读指定版本源码，
产出一份**每条结论都带证据编号**的预检报告，并支持在同一调查里多轮补充材料。

它给的是**根因假设**，不是最终结论；最终根因由开发确认。

## 二、怎么触发

| 场景 | 你做什么 | 结果 |
|---|---|---|
| 新的 Bug | 在群里发消息并 **@机器人** | 新建一个调查，机器人回复预检报告 |
| 补充材料 | **回复机器人那条报告**，或带上报告末尾的 `[TD-xxxxxxxx]` | 进入下一轮，上一轮结论作为上下文 |
| 追加多个 Bug | 每个 Bug 单独 **@机器人** 发一条 | 各自独立调查，互不串消息/上下文/证据 |

报告末尾一定带一行标号，例如：

```
[TD-j640cw9v]
```

## 三、多轮怎么被认出来（路由规则）

一条群消息按以下**优先级**归属到调查，命中即停止：

```
1. 正文里的 [TD-xxxxxxxx]     —— 显式标号
2. root_id / thread_id         —— 飞书线程字段（引用/回复时平台给）
3. parent_id 映射到历史消息    —— 回复某条用户消息
4. 都没有，且被 @              —— 新建调查
5. 其余                        —— 无法关联，不猜归属
```

**冲突处理（已确认的产品决策）**：当“标号”和“引用带来的 id”指向不同调查时，
**以标号为主**。标号是用户显式声明，优先级最高。

## 四、推荐用法

- **最稳**：每次回复都 **@机器人**，并保留报告末尾的 `[TD-xxxxxxxx]`。
- **为什么推荐带标号**：引用（回复）不一定返回 `root_id`，缺了它就只能靠标号认回原调查；
  纯文本回复（不引用）时 `root_id`/`parent_id` 全为空，**标号是唯一依据**。
- 只引用、不带标号：在大多数群里可用（平台会带 `root_id`），但在 `root_id` 缺失的群里会失效。

## 五、权限与准入

- 群聊新会话默认**必须 @机器人**（`FEISHU_REQUIRE_MENTION=true`）。
- 当前按最小权限 `im:message.group_at_msg:readonly` 接入，飞书**只推送被 @ 的消息**。
  因此“线程内回复免 @”需要更宽的读取权限（通常要管理员审批）；拿不到就按“每次 @”约定。
- 机器人 `open_id` 未知时按 **fail-closed** 处理，不会默认放行群消息。

## 六、已知限制

- 报告 `材料不完整(partial)` 表示没拿全材料，不代表根因已确认。
- 当前默认 `TD_ENGINE=fake`（离线确定性引擎）；真实模型需设 `TD_ENGINE=pi`。
- 真实日志平台（SLS/ELK）尚未接入，当前为本地文件日志源。
- 展示格式偏“工程化”，信息密度高，体验待优化（见 `backlog.md`）。
